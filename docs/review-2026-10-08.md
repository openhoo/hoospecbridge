# Review and polish — October 8, 2026

Version: **0.1.1**. Three parallel reviewers covered sync/recovery, API/content, and parser/config/CLI. The integration pass reviewed cross-module behavior, added end-to-end rich-content regressions and improved packaging, documentation and human-readable plans.

## Findings fixed

| Area                  | Concrete failure                                                                                         | Repair                                                                                                                    |
| --------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Create recovery       | A lost response for a completed task could not resume the requested completion                           | Persist completion intent in the pre-request journal and recover it through the stable marker                             |
| Partial sync          | A successful description write followed by a failed checkbox pull conflicted with its own write on retry | Checkpoint content while retaining the previous completion baseline                                                       |
| Mutation verification | A response could claim unpersisted changes or switch issue identity                                      | Verify requested identity, returned structure, and immediate tracker readback before advancing baselines                  |
| Concurrent edits      | A later issue could change while an earlier issue was being updated                                      | Recheck every issue immediately before its update; retain checkpoints for earlier successful writes                       |
| Rich content          | Text-identical Jira links, marks and media changes could be overwritten undetected                       | Store a separate managed-structure fingerprint; detect conflicts and preserve pull-selected content                       |
| Content ownership     | A pull could authorize an unchanged later automatic run to overwrite remote content                      | Keep the recorded content until a new local content change or explicit push                                               |
| Issue indexing        | One issue could claim two tasks, or duplicate issue IDs could be accepted                                | Reject shared/duplicate identities and scan every issue description once                                                  |
| GitLab pages          | Short pages or Link-only pagination could truncate discovery                                             | Follow validated pagination metadata, including server page size, and retain project/scope filters                        |
| Jira pages            | Incomplete cursor metadata could look like a complete result                                             | Reject missing, malformed and repeated pagination metadata                                                                |
| Workflow              | Reopening directly into In Progress was unsupported                                                      | Match any non-done destination and require explicit configuration when ambiguous                                          |
| ADF ownership         | Markers embedded in rich or mixed nodes could remove human content                                       | Require separate marker paragraphs; preserve root metadata and rich notes outside the block                               |
| Task parsing          | Malformed fences and indented examples could become tasks                                                | Respect code-fence boundaries and ignore four-space/tab-indented code                                                     |
| Task metadata         | Reversed tags and empty metadata-only descriptions were mishandled                                       | Parse either tag order, reject repeated tags and empty descriptions                                                       |
| Checkbox batches      | A stale later source file could be found after an earlier file was replaced                              | Preflight every source, reject contradictory changes, reread immediately before replacement, and clean up temporary files |
| Library boundary      | Truthy nonboolean apply values and invalid directions could reach a write/lock                           | Validate runtime options before acquiring a lock                                                                          |
| State                 | Corrupt pending entries, duplicate mappings and false lock diagnoses obscured recovery                   | Validate persisted state, flush journals, and distinguish lock contention from I/O failures                               |
| CLI                   | Inappropriate options were silently ignored and version output was hardcoded                             | Reject command-specific option mistakes and read installed package metadata                                               |
| Packaging             | The CI archive path was version-specific and declarations were not compiled by a consumer                | Install a dynamically packed archive in a fresh project and verify bin, exports, declarations and skill bytes             |

## Qualification

- **83 behavioral tests pass**; 56 added during review.
- Strict source, test and verification-script TypeScript checks pass.
- Formatting and Git diff whitespace checks pass.
- Local HTTP round trips cover both Jira Cloud and GitLab.
- Interrupted writes, conflicting edits, rich-content preservation, pagination and mapping identity have regressions.
- Fresh archive installation verifies npm's CLI bin, sample task scanning, runtime imports, a strict TypeScript consumer and both bundled agent skills.
- State files without structural fingerprints remain compatible and gain them through adoption.
- CodeQL follow-up identified exception text returned without an explicit content type in the local HTTP fixture. The handler now emits JSON with `nosniff`, covered by a regression test.

## Practical limits

These tests use local HTTP fixtures and controlled failure injection. No live Jira/GitLab project was selected. Windows-specific execution was not exercised locally; file flushing is retained and POSIX directory flushing is guarded by platform.

Tracker APIs and multiple local files cannot participate in a shared transaction. Rechecks reduce the race window; they cannot eliminate a concurrent edit after the final check. Use one writer across clones and CI jobs. Changes already applied before a later failure remain recorded for reconciliation.
